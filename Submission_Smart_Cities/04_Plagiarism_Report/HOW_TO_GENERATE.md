# Plagiarism Report

**I cannot generate this** — it requires your institution's licensed tool. Place the
finished report in this folder, e.g. `Plagiarism_Report.pdf`.

## What to submit through

Most likely **Turnitin via VTOP**, or whichever checker your department uses. If you are
unsure, ask the course faculty before 3 November — the queue can take a day.

## What to check

Run it on the final project report:

```
01_Project_Report/Final_Project_Report_Smart_Cities.docx
```

Submit the **.docx**, not the PDF, if the tool accepts both — it parses more reliably.

## What to expect

The report was written for this submission, so the similarity score should be low. Matches
that do appear will mostly be legitimate and should not be "fixed":

| Likely match | Why it is fine |
|---|---|
| Reference list entries | Citations are supposed to match the source exactly |
| Component names and specifications | "ESP32-WROOM-32", "capacitive soil moisture sensor v1.2" have no paraphrase |
| Standard technical phrases | "support vector machine", "transfer learning", "urban heat-island effect" |
| Quoted figures from cited work | e.g. the US$44 baseline cost, attributed to reference [1] |

If the overall score is high, look at **which** sources it matched before rewriting
anything. A high score driven by the bibliography is not plagiarism.

## If it flags your own earlier documents

This project has been submitted to another course. If your institution's database contains
those earlier files, the checker may flag them as self-plagiarism. Two things help:

- The report in this folder was **written fresh** for the smart-city framing — the
  structure (SRS/SDS), the urban framing, the deployment section and the requirements
  tables are all new.
- If flagged anyway, raise it with the faculty proactively rather than waiting to be asked.
  Declaring a prior submission is a different conversation from being caught out by one.
